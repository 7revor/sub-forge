# 可拖动卡片圆角阴影修复（2026-10-30）

按用户此前授权直接在 main 修改。

根因：SortableRow 在直角 li 上绘制 shadow-md，实际边框和 border-radius 在 renderItem 返回的子元素上，导致外形不一致。

修复：外层只保留 relative/z-index 和拖动位移；通过直接子元素选择器把相同阴影绘制在真实行/卡片上，浏览器自动沿用实际圆角。未硬编码卡片圆角，也未改动排序逻辑。

全源搜索确认 useSortable/拖动状态仅由公共 SortableList 实现；已检查全部调用者的实际内容根元素，包括规则、策略组、增强来源、客户端覆盖、组合成员、处理链及成员列表。

## 验证

- web 生产构建（含类型检查）通过，保留既有 bundle 体积提示；git diff --check 通过。此次仅改样式，不新增镜像实现的单元测试。
- Codex 内置浏览器使用隔离内存数据；键盘 Space 进入真实拖动状态，读取 DOM 计算样式并截图。
- 规则、策略组、增强来源：外层 li 的 box-shadow 为 none；实际卡片圆角 10px，shadow-md 在该卡片上显示。
- 组合成员和处理链：实际行为直角行，阴影仍匹配其 0px 圆角；外层不再绘制第二份阴影。
- Escape 取消后，实际卡片和外层的 box-shadow 均恢复 none，无残留。
- 仅直接内容元素获得拖动阴影，不将其添加到内部输入框、图标或嵌套列表项。
