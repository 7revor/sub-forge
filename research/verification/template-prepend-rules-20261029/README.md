# 绑定订阅前置规则验收

日期：2026-10-29。使用 Codex 内置浏览器与独立 worktree、内存数据库、虚构账号及模拟远端节点，不读取真实订阅或业务数据库。

## 实现与检查

- 绑定模式新增可选 `routing.prependRules`，按保存顺序排在全部模板规则之前。缺省为空，既有绑定订阅无需新增迁移。
- 前置增删、编辑、开关和排序复用全局规则编辑器、出口选择器与排序组件。固定单条匹配，不提供规则集类型或任意插入位置。
- 模板规则的类型、顺序、启用和出口、MATCH 保持只读。
- 内置策略、模板策略组、单节点三种出口已在内置浏览器添加成功；未选择节点时禁止插入。
- 通过键盘拖动将远端节点规则从第三条移到第二条，保存并刷新后顺序保留。
- 实际预览中，远端节点被精确筛入隐藏依赖组，出口引用该组；没有直接引用 provider 内部节点名。生成前置规则、模板规则、MATCH 顺序正确，报告零错误、零告警。
- 已在浏览器编辑第一条规则、停用第三条并保存，再删除第三条并保存；最终预览只含编辑后的第一条、远端节点规则及模板规则、MATCH。
- API 和内核测试覆盖 wrap/copy/inline 依赖、与代理链重复引用复用、缺失节点兜底、保存/重读/草稿预览/实际订阅、模板更新、绑定转独立、重新绑定时组出口映射、非法匹配项/位置/引用/所有权校验、模板发布冲突与不可 force。前置规则抽出的本地节点副本在全部规则出口解析后参与链环检查，覆盖 include-all-proxies 引入自身环的场景。
- 接入双模式最终提交并解决主干兼容冲突后，类型检查、前端生产构建和全量测试通过：core 200、server 353、web 272，共 825 项通过、46 项按现有条件跳过。跳过项不记为通过。示例种子去除未填写的远程地址后，在内存库成功导入并渲染前置规则。
