# Mihomo 配置的多端可移植性验收

日期：2026-10-30。测试对象为 `codex/surge-loon-output` 工作树的四客户端渲染管线，包含本轮端口集合修复 `d398e37`。尚未合并、部署。所有服务器、密码、UUID 和 Reality 公钥都是测试数据。

## 结论

**可以共用一套已适配的节点和分流模型，但不能把整份 Mihomo YAML 的所有字段自动等价转换成 Surge、Loon、Stash。** 本项目将节点、策略组、规则先放入共用模型，再生成客户端格式；基础设置则按客户端分别保存和合并。

本次覆盖 77 个配置场景、四端共 308 次生成，另有字段映射、单位、出口、成员、导入及基础配置隔离断言。44 个场景四端生成时没有错误、警告或规则丢弃，但其中仍包含版本要求、算法差异和直接透传字段，**44 不能解释为 44 项真实运行完全等价**。全部结果在[逐项矩阵](matrix.md)和[机器可读结果](matrix.json)。

| 范围 | 建议采用的公共子集 | 边界 |
| --- | --- | --- |
| SS | `aes-128-gcm`、`aes-256-gcm`、`chacha20-ietf-poly1305`，密码；simple-obfs 的 http/Host | 只验证列出的组合；不能推广到全部插件和所有加密方式 |
| VMess | AEAD：`alterId: 0`、`cipher: auto`；TCP/TLS，或 WS/TLS 加单个 Host/path | Surge 不接受本次测试的非零 alterId、none 加密、gRPC；Loon 无法保留 WS 任意自定义请求头 |
| Trojan | TCP/TLS、密码、SNI、`skip-cert-verify: false`、ALPN | Trojan WS 不是四端公共项 |
| HTTP / SOCKS5 | HTTP(S)、SOCKS5/TLS，已测用户名密码和 TLS 开关 | 未测试的协议专有选项不作保证 |
| AnyTLS / Hysteria2 | 已测基础认证/SNI；Hy2 下行 Mbps、Salamander、端口跳跃 | 需要支持该协议的客户端版本；Hy2 上行限制会被 Surge/Loon 省略 |
| 策略组 | `select`、节点成员、嵌套组 | 客户端图标与显示选项单独看，不据此判断路由是否等价 |
| 自动组 | `url-test` / `fallback` 的已测 url、interval、timeout；url-test tolerance | 测速位置和实现不同，见下文；不保证选中相同节点 |
| 确定性规则 | `DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`IP-CIDR` / `IP-CIDR6`、`no-resolve`、单端口、DIRECT/REJECT/最终出口 | IPv6、DNS 和系统接管方式另行配置；涉及不同类别规则交叉时须核对 Loon 优先级 |
| 有条件规则 | 基本 `DOMAIN-WILDCARD`、IP-ASN/GEOIP、NETWORK、源端口、AND/OR/NOT、端口集合 | 通配/逻辑/源端口有版本要求；地理库不同会影响结果；协议分类也需真机验证 |

节点中的 `server`、`port`、密码/UUID、TLS/SNI/ALPN 等均检查了具体输出字段；显式 `false` 未被当作空值丢弃。节点测试还经完整 Mihomo YAML 的节点导入入口复核，确认传输字段与凭据保留。这里的“完整 YAML 导入”只提取节点，**不会自动导入它的基础配置、外部组和分流规则**。

## 不能直接作为四端公共配置的项目

- **基础设置**：`dns`、fake-ip、nameserver-policy、`tun`、`sniffer`、监听端口、external-controller、listeners、routing-mark 等不在统一基础配置转换范围。服务层测试确认：仅设置 Mihomo 的 DNS/TUN/端口，不会出现在其他三端；添加各自的预设和覆盖后，才进入对应产物。即使字段名相似，也不能据此假定行为等价。
- **节点协议与传输**：Surge 这层未适配 VLESS/Reality、SSR、ShadowTLS、v2ray-plugin、gRPC、Trojan WS；Loon 这层未适配 TUIC、Snell、v2ray-plugin、gRPC。代理链不属于 Loon 的当前输出能力。Mihomo `smux` 不能四端通用。
- **高级参数**：Surge 会省略 `client-fingerprint`；Surge/Loon 会省略 Hy2 `up`、部分 lazy/显示/测速设置。`expected-status`、`max-failed-times`、`sticky-sessions`、组扩展参数等不能按 Mihomo 原样全端使用；具体是警告还是报错见矩阵。
- **规则**：GEOSITE、DOMAIN-REGEX、源 IP 匹配、进程规则不是当前 iOS 四端公共项。Surge/Loon 的不支持项会产生规则丢弃诊断，可能仍生成整份订阅，不能只看预览“成功”。USER-AGENT、URL-REGEX、Surge extended-matching 也不属于 Mihomo 四端公共规则。
- **原文和资源**：RAW 规则、未知扩展参数没有自动语义保证。Mihomo 的 provider 机制不会原样保留到 Surge/Loon，节点转为快照内联；Loon 规则集也会展开。二进制 MRS/SRS 不在此次公共样例范围，不宣称可直接转成 INI 客户端规则。

这是本仓库当前适配范围，不是各客户端原生能力的完整列表。例如 Stash 官方支持 URL-REGEX，而本项目当前会省略；SS2022、WireGuard 等未在本轮 77 场景中穷举，不能从未覆盖推断原生不支持。

## 需要明确的语义差异

1. **基础配置彼此独立**：Mihomo 使用 `preset.mihomo + base.patch`，Surge、Loon、Stash 分别使用自己的 preset 字段和 `surgePatch` / `loonPatch` / `stashPatch`。代码不会猜测 DNS 或 TUN 的对应含义。
2. **测速配置的位置**：Mihomo 放在组上，Surge/Stash 下放节点，Loon 的单次超时放在 General。`5000 ms` 分别映射为 `5 s`；Loon fallback 的 `max-timeout` 仍为毫秒。多组共享节点时测速 URL/超时要一致，Loon 全局超时也要一致，否则拒绝输出。
3. **负载均衡**：consistent-hashing 转 Surge persistent / Loon PCC，仅保留“按目标主机稳定选择”的意图，不保证相同哈希或相同出口。round-robin 无法转换为 Surge 的等价算法，sticky-sessions 不能四端共用。
4. **规则优先级**：Loon 自 3.0.3 起有域名、IP、其他规则的分阶段匹配；即使文件顺序一致，交叉命中结果也可能不同。通用模板应避免依赖不同类别的相互覆盖，必要时设置客户端覆盖并实测。[Loon 官方规则说明](https://nsloon.app/en/docs/Rule/)
5. **版本和数据库**：Loon 逻辑/端口规则要求 3.1.7+，DOMAIN-WILDCARD 要求 Build 1008+；Stash SRC-PORT 官方标为 iOS/tvOS 3.7、macOS 4.4 的 Beta 能力。GEOIP/ASN 必须使用一致的数据才可能得到一致命中；只通过语法检查不能证明这一点。[Loon 逻辑规则](https://nsloon.app/en/docs/Rule/logic_rule/)、[Loon 端口规则](https://nsloon.app/en/docs/Rule/port_rule/)、[Stash 规则](https://stash.wiki/rules/rule-types)
6. **透传不等于适配**：Stash 会直接透传不少节点字段。例如本次 `tfo` 生成成功，但官方节点文档未确认相同字段，因此未纳入推荐参数。Stash 的 QUIC 默认拦截也会影响 UDP 使用，不能只靠 `udp: true` 推断所有客户端网络行为一致。[Stash 节点说明](https://stash.wiki/en/proxy-protocols/proxy-types)

## 本次发现并修复

初次官方校验发现：`DST-PORT,80/443` 输出成 Surge `DEST-PORT,80/443` 后，Surge 拒绝加载。修复后对 Surge、Loon、Stash 生成等价 OR：

```text
OR,((DEST-PORT,80),(DEST-PORT,443)),代理
```

Stash 子规则仍用 `DST-PORT`，Mihomo 保留原生斜杠集合。源端口集合、集合中的闭区间、逻辑嵌套和出口一并保留。畸形集合会整条拒绝，不能仅删除坏成员而改变匹配范围。新增回归检查及 Surge 官方校验样例。旧写法保留为负面对照，仍被 Surge 明确拒绝。[Surge 端口表达式](https://manual.nssurge.com/rules/source-and-port.html)、[Surge 逻辑规则](https://manual.nssurge.com/rules/logical.html)

初次 Reality 样例使用占位公钥而被 Mihomo 拒绝；现已改为固定生成的有效 X25519 测试公钥，避免把无效测试数据误判成协议不支持。这个公钥不对应任何实际服务。
