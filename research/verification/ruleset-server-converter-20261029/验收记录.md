## 内置浏览器验收

使用 Codex 内置浏览器、隔离内存数据库和人工构造的规则，后台服务地址为 127.0.0.1:18761，前端为 127.0.0.1:18762。没有访问生产数据，没有使用 Playwright CLI、MCP 或外部浏览器。转换响应刻意延迟 800ms。

| 场景 | 结果 |
|---|---|
| 初次加载两个来源 | 两次来源请求、一次上游读取、一次转换请求 |
| 从 mihomo 切到 Surge iOS，再切到 Surge macOS | 来源请求仍为两次、上游仍为一次；只新增两次转换请求 |
| 名称和备注编辑 | 来源与转换请求计数均不增加 |
| 格式错误和未实现解析 | 上方只显示两条来源诊断：USER-AGENT 未实现、DOMAIN 缺少值 |
| Surge iOS 进程规则 | 上方未解析数量不变；下方显示本地与远程两条客户端无法输出诊断 |
| 切换其他来源 | 固定高度区域保留，不把上一来源的正文当作新来源显示 |
| 编辑本地来源 | 更新该来源解析与转换，旧结果在等待期间继续显示并标注 |
| 模拟转换 503 | 保留旧文本及旧客户端标识，显示“重新转换”；恢复后重试成功 |
| 稳定性复测 | 更新前、中、后的输出区域均为 111 行、高 420px、内部 scrollTop 720、位置 y=440 |

## 行号含义与范围

固定输入和改写配置下，不同客户端的输出行位一致。预留行使多条替换与追加不会挤动后续行；YAML 流式输入会展开为逻辑行，使用返回的来源行号定位原文。这里没有承诺修改源文件或增删改写配置后仍维持原输出行号。
