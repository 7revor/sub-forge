# 存储结构整理验证

日期：2026-11-02。基线：`main@ee74ee5`。未修改真实数据库，未推送，未部署。

## 改动

| 项目 | 结果 |
| --- | --- |
| 迁移边界 | 升级步骤、旧种子转换和历史模板读取移入 `store-migrations.ts`，当前结构移入 `schema.ts`。没有新增迁移框架、仓储继承层或插件系统，迁移备份和规范化保护全部保留。 |
| 模板读取 | 移除 `legacyTemplateMode`。`getTemplate` 和模板查询只读 `templates`，迁移事务显式传入历史读取函数。 |
| 刷新任务 | `refresh_jobs` 纳入 `SCHEMA`，结构版本升到 v32。`ResourceService` 通过删除事务内的钩子清理任务，不再探测 `sqlite_master`。 |
| 绑定清理 | 只解密来源、规则集和订阅，共享规则和规则集不重复解密。 |
| 资源状态 | `SnapshotService.status`、`statuses` 和 `all` 只读；调度和刷新任务在拉取前绑定。 |

结构版本必须升级：只被 Store 打开过的 v31 库可能没有 `refresh_jobs`，而 `ResourceService` 不再建表。

## 实测依据

一次性脚本，内存数据库，15 次清理取中位数。规模“50 / 500”表示来源、组合、规则集、订阅、共享规则各 50 个，另有 50 个 500 节点的本地组。

| 规模 | 指标 | 调整前 | 调整后 |
| --- | --- | --- | --- |
| 50 / 500 | 单次清理解密次数 | 450 | 250 |
| 50 / 500 | 单次清理解密字符数 | 3,896,510 | 50,390 |
| 50 / 500 | 单次清理耗时 | 15.94 ms | 2.76 ms |
| 10 / 50 | 单次清理解密字符数 | 90,430 | 9,950 |
| 10 / 50 | 单次清理耗时 | 1.26 ms | 0.68 ms |
| 50 / 500 | 50 次 `status` 写入行数 | 50 | 0 |

调整前本地节点组占解密量的 98%，但清理逻辑从不使用其内容。这是合成数据的结果，不代表线上发现过性能瓶颈。

## 差分验证

用同一批夹具分别运行基线和当前 `Store`，比较全部表的解密内容、结构和错误信息。只允许结构版本号（31 / 32）和 `refresh_jobs` 不同，随机 ID 和令牌做掩码处理。

| 场景 | 结果 |
| --- | --- |
| 从 v0、2、4–8、14–16、18–30 共 23 个版本升级；覆盖明文加密、本地来源、规则包、锁定版本展开、预设退役、旧凭据、原始备份 | 全部升级成功，结果一致 |
| 升级后重新打开 | 一致 |
| 升级后导入旧种子（锁定版本、规则包、预设、本地内容来源） | 一致 |
| 锁定版本缺失的旧库 | 均报同一错误，事务回滚，结果一致 |
| 在已有模板和绑定的库上导入失败的种子 | 均回滚，结果一致 |
| 在已有模板和绑定的库上导入覆盖模板的种子 | 一致 |

脚本依赖基线源码副本，属于一次性验证，未纳入仓库。夹具不是真实用户数据，不代表对现有数据库逐行审计。
