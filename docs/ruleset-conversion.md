# 规则来源获取与服务端转换

## 职责边界

规则集页面保留 mihomo、mihomo Android、Surge macOS、Surge iOS 切换。浏览器只保存原文、编辑草稿和选择状态，不执行解析、改写、去重或客户端转换。

- `RuleSourceService` 获取来源原文，返回拉取状态和解析诊断。已保存且读取参数未变化的远程来源沿用正式快照；草稿或修改后的读取参数使用隔离的短期缓存，不写正式快照。草稿按用户、地址、格式和拉取参数缓存，合并重复请求，上游同步读取最多并发四个。
- `RuleConverter` 不做网络或数据库访问。它接受原文、来源元数据、改写及客户端上下文，调用共享内核；解析结果按内容缓存，最多 64 项、约 16 MiB 序列化数据。
- `prepareRuleDocument` 和 `convertRuleDocuments` 为共享纯函数。管理接口及实际托管 LIST 文件调用相同的转换函数。原始透传仍遵循已有的输出格式判定。
- `useRulesetSources` 按来源缓存原文和诊断。名称、备注、客户端选择和改写不进入来源获取键。
- `RulesetPreview` 内部保存客户端与平台，仅请求服务端转换。更新保留旧输出并明确标注；切换到其他来源不冒用旧来源结果；失败可重新转换。

## 接口

### 已保存来源读取

`GET /api/rulesets/sources/content?id=ID&source=来源ID`

必须登录且拥有规则集。返回 `{ content?, status }`。二进制来源不伪造文本正文。

### 草稿来源读取

`POST /api/rulesets/source`

请求 `{ id?, source, refresh? }`。`source` 包含来源 id、kind、地址或本地 content、format、repository、behavior、fetch；不要求先保存。可选 `refresh: true` 显式重新获取来源，绕过失败退避和已完成的草稿缓存；并发刷新仍复用在途请求。该接口与 GET 共用 getter。使用 POST 是为了承载草稿正文和未保存参数。

`status` 的 `rules` 是解析成功数量，`rejected` 是格式错误或系统尚未支持解析的数量，`rejectedDetails` 最多包含 100 条详情。原文不截断；未解析的内容仍保留。目标客户端能力不参与这份状态。

### 通用转换

`POST /api/rules/convert`

请求示例：

```json
{
  "inputs": [{
    "source": { "id": "local", "kind": "local", "format": "auto" },
    "content": "DOMAIN,example.test\nPROCESS-NAME,Example\nUSER-AGENT,x*"
  }],
  "client": "surge",
  "platform": "ios",
  "overrides": []
}
```

可选 `sourceId` 选择单来源，否则合并启用来源。返回 `lines`、`origins`、`diagnostics`、`stats`、`delivery`、`passthrough`。

- `origins` 与 `lines` 一一对应，记录源 id 和源行号；组级追加使用 `$append` 定位到改写条目。
- `stats` 分开记录解析成功、未解析、改写移除/替换/追加、重复、客户端无法输出、降级、有效输出，以及有效输出的 domain/classical/ipcidr 数量。
- 转换不读取传入 URL；当前预览范围内的文本来源缺少正文时返回 400，不输出空或部分成功结果。禁用来源（未单选）与二进制透传不受此限制。
- 请求体上限 16 MiB，最多 256 个来源。超过限制拒绝请求，不截断计算输入。
- 旧 `POST /api/rulesets/preview` 保留为组合接口，内部只编排 getter 和 converter；新页面不使用它。

## 行号与注释

转换按来源顺序和源文件顺序输出，不再为了统计按 domain/classical/ipcidr 重排。分类仅用于统计。

- 原注释和空行保留，LIST 不兼容的注释形式转为 `#`。
- 输入错误、系统尚未支持解析、改写移除、重复及客户端无法输出均保留为注释，不删除对应位置。
- 一条规则可能替换为多条时，依据全部客户端配置的最大展开宽度预留位置；未占用位置写注释。组级追加不匹配当前客户端时也保留注释。
- 相同来源和改写配置下，四个客户端结果行位一致；增加来源、修改原文或改变改写条数会改变布局。
- YAML 结构行转注释，条目关联原文件物理行。流式 YAML 同一物理行包含多条规则时按条目展开；输出行号并不等于 YAML 物理行号，应使用 `origins` 定位。
- 注释和预留行不计入有效规则数量。
- 单来源预览保留现有语义：可以查看禁用来源，不执行整组去重及组级追加。

## 界面诊断

来源区只显示“已解析 N 条 · 未解析 M 行”。弹层区分“输入格式有误”和“本系统暂未支持解析”，不显示客户端能力问题。

预览区单独列出“客户端无法输出”、降级和改写信息。源解析问题在输出中的原位置保留注释。固定文本区高度并始终挂载，更新时不以短小加载提示替换正文；详情默认折叠。

## 验证边界

`USER-AGENT` 已支持解析：Surge macOS / iOS 正常输出，mihomo / Android 保留为“当前客户端无法输出”的注释，计入客户端不支持数量，不计入来源未解析数量。匹配值保留大小写，支持 Surge 的 `*` / `?` 通配符（[官方 HTTP 规则文档](https://manual.nssurge.com/rules/http.html)）。逻辑规则仍未支持。不会依据 URL 名称猜测客户端能力，也不会把未知规则变成可执行透传规则。原始直连与二进制规则的既有能力边界保留。

## 来源新鲜度与失败恢复

- 编辑器读取已保存来源时，过期快照等待刷新完成后返回；订阅仍使用 stale-while-revalidate，不因编辑器读取策略而等待过期上游。
- 所有已保存来源的重试都经过正式快照写入，不再使用只返回正文但不写快照的隐式补读。刷新失败保留最后成功快照，返回 `status.ok: false`、`error` 和 `stale`，不将旧正文包装成刷新成功。
- 草稿失败不缓存；显式刷新跳过成功缓存，读取过程中的重复请求共用同一个 Promise。
- 来源失败与转换失败分别提供“重新读取来源”和“重新转换”。来源失败时停止新的转换，保留上次预览并标注过期；无历史结果时明确显示尚无可用预览。HTTP 错误和 HTTP 200 中的来源业务错误均按此处理。
- 正常预览不显示下载说明和“刷新来源”按钮，读取失败时仍提供“重新读取来源”。客户端切换继续复用父页面缓存，不重新读取上游；预览代表上次读取的来源版本，不承诺与持续变化的远程文件实时同步。
- 实际托管输出的校验、输出方式判断与正文生成复用容错文档。畸形本地 YAML 写为注释，不再被旧解析路径提前抛异常；远程错误页面和完全无有效规则的快照继续阻止生成空分流配置。
- 同一输入与配置下，mihomo / Android 的托管 LIST 与预览逐行一致。原始直连仍下载上游原文；Surge 主订阅输出当前返回 501，四客户端转换及行位校验不代表已实现 Surge 主订阅下发。

## 外部 URL 与系统 ID 引用

模板和订阅私有规则支持三种入口：单条规则、系统规则集（规则增强 / 仓库）和远程 URL。

- 系统规则集继续保存原 ID 或仓库映射，保留权限、多来源、改写和已有输出策略。不会因为某个来源地址与外部 URL 相同而自动替换引用。
- 外部引用保存 `{ kind: "ruleset", id: "remote:<URL 派生键>", remote: { url } }`。派生键仅用于去重、快照及 provider 隔离，不创建规则增强记录。服务端验证 URL 与键相符；不允许同时携带仓库映射。
- 外部引用默认强制输出 classical `.list`，内容由现有解析、去重、客户端适配链路生成。`no-resolve` 只由来源文件逐行决定；历史规则集级或引用级开关均忽略。`src` 仍参与输出和资源身份。
- YAML 导入的 `rule-providers` 只提取 HTTP(S) URL，通过 `RULE-SET` 的名称关联出口；忽略上游 `path`、`interval`、`format`、`behavior`。单独导入 `rule-providers` 时补入当前模板，保留组、已有规则和 final，新规则默认 REJECT。无远程 URL 的本地 provider 明确报错。
- 应用自身导出的引用映射保留系统 ID 和 URL 身份，支持表单 / 原始配置往返；显式系统引用映射优先于同名 provider。普通导入不按名字匹配或覆盖系统规则集。

### URL 下载转换接口

`GET /api/rules/convert?url=<编码后的完整地址>&target=mihomo&format=list`

- 默认 target 为 mihomo，format 为 list；target 也可为 surge，可选 platform。需要已登录会话，成功返回 `text/plain` 及 `rules.list` 下载文件名；不会返回 JSON 包裹的正文。
- 上游 URL 必须整体编码，包括它自身的查询参数。地址仅接受 HTTP(S)，沿用上游访问限制、重定向校验、超时、大小限制和缓存。
- `x-rule-count` 表示有效输出，`x-rule-rejected` 表示未解析或客户端无法输出数量；无法输出的行保留注释。完全没有有效规则时返回 400，上游读取或二进制解码失败返回 502。
- POST 转换仍只接收已获取正文，不进行网络访问。GET 组合来源获取与相同转换器；客户端切换不重复读取上游。

订阅渲染会自动生成可嵌套到 `rule-providers.url` 的 GET 地址，额外包含 `token`、`key` 和结构版本 `v`。客户端不需要登录。服务端先核对订阅 token、版本、资源键及完整 URL，只允许下载该订阅已生成的外部规则；参数不能改成其他地址。规则正文沿用快照和 last-good，旧版本保留自己的来源与规则选项，token 撤销后地址立即失效。这个接口不会让服务端再 HTTP 请求自身，内部直接复用渲染与转换结果。

### MetaCubeX / MRS 兼容范围

[MetaCubeX/meta-rules-dat 的 geosite 目录](https://github.com/MetaCubeX/meta-rules-dat/tree/meta/geo/geosite) 提供 LIST、YAML、MRS。不能仅凭 `.list` 后缀认定是 classical：裸域名、`+.` 后缀域名、Clash 子域通配按实际语义转为规则行，已知 MetaCubeX 原始文件路径使用 Clash 域名方言。

自动读取根据内容识别 MRS 的 Zstd 魔数，实现 MRS v1 的 domain / ipcidr 数据解码，然后送入共享转换器。无需外部 Mihomo 程序，也不会将 `.mrs` 地址替换为猜测的同名 `.list` 地址。Node.js 需 22.15 或更新版本的 Zstd 支持；旧 Node.js 明确返回原因。解码设置压缩输出、节点数、域名深度、规则数和文本大小上限；损坏、截断或未知版本不生成成功文件。解码文本带内部注释标记，防止系统规则增强将转换后的正文误判为可以直接下载原二进制 URL。

旧数据显式选择 MRS / SRS 透传时仍保留原策略。新外部 URL 均自动识别；SRS 尚无解码器，返回明确的不支持错误。逻辑规则等原有未实现能力不因新增 GET 接口而改变；USER-AGENT 沿用上述按客户端输出规则；Surge 主订阅仍未开放。

### no-resolve 以规则内容为准

规则集、规则增强、模板和订阅均不提供独立 no-resolve 开关。远程来源保留文件每一行自己的标记；本地单条、替换和追加规则以实际原文有无 `,no-resolve` 为准，不自动补加。YAML 导入保留单条规则内的标记，忽略 `RULE-SET` 引用后的独立 `no-resolve`。

数据库 v18 清除旧规则集 `noResolve` 和规则引用 `options.noResolve`，不改写来源文件、单条原文或已有结构化规则内容。预览、转换、下载与渲染统一忽略旧字段；已发出的历史资源仍保留原版本。
