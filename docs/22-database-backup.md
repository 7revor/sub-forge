# 数据库定时备份与 WebDAV 恢复（SYS-07）

2026-11-02 实现，替代原“导出全部配置为 JSON”的需求。入口在系统页「数据库备份」，仅管理员可用。

## 备份内容与格式

一份备份是 SQLite 一致性快照加主密钥，上传前用备份口令加密：

```text
SFBAK1\n + 头部 JSON\n + AES-256-GCM(gzip(32 字节主密钥 + SQLite 文件)) + 16 字节认证标签
```

- 文档与快照正文由主密钥加密，令牌与地址索引由它派生的 HMAC 计算，换机恢复必须带上主密钥；所以整包用独立口令加密（scrypt N=2^15, r=8, p=1），WebDAV 服务方读不到内容。
- 头部记录创建时间、结构版本和 KDF 参数，作为附加认证数据；解密时只接受当前版本写入的 KDF 参数。
- **备份口令丢失后备份无法解密，服务端也无法找回。** 当前实例保存了口令时可直接恢复；换机恢复需要手动输入。
- 规则仓库 Git 缓存（`rule-repo-cache`）不在备份内，恢复后按需重新拉取。

## 定时与保留

- 配置（WebDAV 地址、账号、密码、口令、间隔、份数）和最近状态用主密钥加密，存于 `system_settings` 的 `backup`、`backupState`，接口只返回 `hasPassword` / `hasPassphrase`。
- 调度每分钟检查一次，上次尝试后超过间隔就运行；失败不重试，到下一个间隔再试，错误显示在系统页。从未备份时启用后一分钟内运行。
- 文件名为 `sub-forge-YYYYMMDD-HHmmss.sfbak`（UTC）。上传后核对文件存在且大小一致，然后才按份数清理；只清理这种命名的文件，不碰目录里的其他内容。
- WebDAV 地址可以是内网（如 NAS），不套用订阅上游的地址限制：只有管理员能配置。重定向一律报错，避免凭据被带到配置之外的地址；更换站点时不沿用已保存的密码。建议使用 HTTPS，否则 Basic 凭据是明文传输（备份文件本身仍是加密的）。

## 恢复流程

1. 下载并用口令解密，认证失败直接报错，当前数据不受影响。
2. 拒绝结构版本高于当前程序的备份；`SUBFORGE_SECRET` 与备份主密钥不一致时拒绝（不能替换环境变量）。
3. 写入 `<数据库>.restore/`，打开一次以执行迁移并运行 `integrity_check`，写入当前的 WebDAV 配置（恢复目标是业务数据，这份配置刚验证可用），完成后写 `ready` 标记。
4. 服务停止接收请求、关闭数据库，在**同一进程内**替换数据库和 `secret.key` 后重新启动，不依赖容器重启策略。原文件保存为 `<数据库>.before-restore` 和 `secret.key.before-restore`，下次恢复时覆盖。
5. 替换步骤可重入：进程中途崩溃，下次启动从暂存目录继续；没有 `ready` 标记的暂存目录直接丢弃。

前端用 `/healthz` 的 `x-boot-id` 响应头判断重启完成，随后回到首页。恢复后会话以备份内容为准，可能需要重新登录；连接排空期间（最多 10 秒）旧进程对已有连接的写入不会保留。

## 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/system/backup` | 配置（不含凭据）、运行状态、下次时间 |
| `PUT /api/system/backup` | 保存配置；密码、口令留空保持不变 |
| `POST /api/system/backup/test` | 用草稿测试连接，目录不存在时创建 |
| `GET /api/system/backup/files` | WebDAV 上的备份文件，新的在前 |
| `POST /api/system/backup/run` | 立即备份 |
| `POST /api/system/backup/restore` | `{ name, passphrase? }`，校验通过返回 202 并重启 |
