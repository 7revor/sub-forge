# 数据库手动备份与恢复（SYS-07）

2026-11-02 首版为定时加密备份到 WebDAV，替代原“导出全部配置为 JSON”的需求。2026-11-03 移除 WebDAV、定时任务和备份口令，改为手动下载、手动上传，文件不再加密。入口在系统页「数据库备份」，仅管理员可用。

## 备份内容与格式

一份备份是 SQLite 一致性快照加主密钥：

```text
SFBAK2\n + 头部 JSON\n + gzip(32 字节主密钥 + SQLite 文件)
```

- 令牌与地址索引由主密钥派生的 HMAC 计算，换机恢复必须带上主密钥。
- **文件不加密。** 里面有主密钥、订阅令牌、节点凭据和订阅地址，拿到文件等于拿到全部数据，由管理员自行保管。
- 头部记录创建时间和结构版本。文件完整性靠 gzip 校验和恢复时的 `integrity_check`。
- 文件名为 `sub-forge-YYYYMMDD-HHmmss.sfbak`（UTC），服务端不留副本，也不记录备份历史。
- 规则仓库 Git 缓存（`rule-repo-cache`）不在备份内，恢复后按需重新拉取。备份包含节点快照，不含已清理的规则快照；规则快照到期立刻删除，恢复后下次请求时重新读取。
- 旧版加密备份（`SFBAK1`）不再支持恢复，上传时明确报错。

## 恢复流程

1. 校验文件头并解压；上传限 512 MB，解压后限 2 GB。失败直接报错，当前数据不受影响。
2. 拒绝结构版本高于当前程序的备份；`SUBFORGE_SECRET` 与备份主密钥不一致时拒绝（不能替换环境变量）。
3. 写入 `<数据库>.restore/`，打开一次以执行迁移并运行 `integrity_check`，完成后写 `ready` 标记。
4. 服务停止接收请求、关闭数据库，在**同一进程内**替换数据库和 `secret.key` 后重新启动，不依赖容器重启策略。原文件保存为 `<数据库>.before-restore` 和 `secret.key.before-restore`，下次恢复时覆盖。
5. 替换步骤可重入：进程中途崩溃，下次启动从暂存目录继续；没有 `ready` 标记的暂存目录直接丢弃。

前端用 `/healthz` 的 `x-boot-id` 响应头判断重启完成，随后回到首页。恢复后会话以备份内容为准，可能需要重新登录；连接排空期间（最多 10 秒）旧进程对已有连接的写入不会保留。

## 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/system/backup/download` | 生成并下载备份文件；已有备份或恢复任务时返回 409 |
| `POST /api/system/backup/restore` | 请求体为备份文件原文（`application/octet-stream`），校验通过返回 202 并重启 |

上传是 CSRF 守卫里唯一放行非 JSON 请求体的接口：`application/octet-stream` 不是简单请求，跨站时同样会被预检拦下。

## 升级

v38 迁移删除 `system_settings` 里的 `backup`、`backupState`（WebDAV 账号、密码、备份口令），WebDAV 目录里已有的文件不受影响，需要自行清理。
