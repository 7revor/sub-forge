# 全局托管、用户鉴权与资源生命周期

本契约自 SQLite v23 起生效，替代旧的单订阅 token、上游 URL 透传和按订阅生成规则下载地址的设计。

## 权限与身份

| 对象 | 资源身份 | 下载权限 |
| --- | --- | --- |
| 配置订阅 | 配置 ID + 客户端/平台 | token 有效、用户未禁用、配置属于该用户 |
| 节点源、组合、本地节点 | 节点对象及其依赖 | 同上，整个依赖树都属于该用户 |
| 配置内的节点 provider | 配置 ID + 结构版本 + 节点集 | 同上；历史版本仍检查其节点依赖归属 |
| 规则集合文件、规则增强 | 公共规则身份 + 有效处理参数 + 客户端/平台 | 任意有效且未被禁用的用户 token |

用户创建时原子生成一个独立 token。读取、保存或复制配置不轮换 token；复制后的配置 ID 不同，所以完整订阅链接不同。账户页可以复制或重置 token；重置立即撤销该用户所有旧主订阅、节点及规则链接，其他用户不受影响。令牌是持有者凭证，不限制转发，泄漏后应重置。

公共规则允许任意登录用户读取、引用、预览和刷新。规则增强仅创建者或管理员能修改、删除；删除检查所有用户的配置和公共模板引用。节点和配置始终按用户隔离，不能借预览、组合成员、旧版本或失败回退读取他人节点。下载在异步处理前后重新检查凭证。

节点源、组合、本地节点组、配置订阅和规则增强的列表与详情支持复制链接，使用当前登录账户的 token。只读公共规则也能复制，未保存的节点或规则草稿不能复制。增强集合可独立使用，无需先建立配置订阅；客户端首次访问才生成公共产物，首次失败不留下空产物。登录、退出和会话失效时清空前一账户的查询缓存，晚到的链接查询不能污染新账户；重置令牌会刷新页面上的链接。

## 托管与缓存

节点先应用处理链，再由服务端把代理链写到匹配节点。整集和局部链共用此路径；Mihomo 不生成 provider 级 `override.dialer-proxy`。Stash 继续使用现有的节点快照内联输出，客户端适配差异保留在渲染器内。

文本规则统一解析、改写、去重、按客户端转换为 classical LIST。格式不兼容与附加处理不再决定下载是否经过服务端；不可表示的规则保留转换诊断。单一有效 MRS 来源校验后原字节托管，不能合并、改写或添加 src；SRS 尚不支持。含 MRS 的 Stash 预览不提供独立文本导出。

公共产物用 SHA-256 资源键定位，用户、token、订阅 ID、规则出口组和显示名称不参与资源键。不同客户端/平台、影响正文的 src 参数和输出格式/behavior 生成不同变体。文本改成 MRS 时使用新资源键，旧文本地址保留成功文本并告警，防止旧配置收到二进制；刷新主订阅后使用新地址。配置快照只保存公共资源键，不再复制规则正文。公共规则地址不含原始上游 URL；固定变体 `/r` 不接受下载参数来改变资源定义，独立增强 `/rules` 根据客户端选择对应公共变体。

原文缓存按地址、有效拉取参数共享；公共规则跨用户共用，私有节点按用户隔离。系统统一 TTL，默认 24 小时；后台最多 4 个并发拉取，未浏览或引用的仓库文件不预抓取。过期请求等待合并的在途拉取，失败保留最后成功原文并延后一个周期。公共规则下载单独刷新其来源，不重新生成整个订阅；输入摘要未变时复用已转换产物，同一资源并发下载合并。转换失败保留成功产物，系统页显示错误，响应头 `X-Sub-Forge-Warning: last-good-rule` 标识回退。

## 节点流量信息

独立节点链接按 UA 或显式 target/platform 适配 Mihomo、Stash，并在 `Subscription-Userinfo` 响应头提供上游返回的 upload、download、total、expire。GET 和 HEAD 的响应头相同，HEAD 没有正文；主配置内的 `/p` 也带对应节点集的流量，不误用整个配置的汇总。未知 UA 默认 Mihomo，Surge 节点输出暂返回 501。

单源保留上游已知字段和零值；组合递归收集成员，按同一个上游 URL 去重后累加 upload/download/total，到期取已知最早值。纯本地节点和没有流量信息的来源不生成虚假数值。成功刷新但未返回流量头时清除旧流量；拉取失败则随最后成功快照保留流量。节点筛选不改变上游账户的真实套餐额度。不同 URL 即使属于同一套餐也无法可靠自动识别，仍按不同来源计算。

Stash 的请求约定见官方[机场订阅文档](https://stash.wiki/features/service-provider-subscription)，其服务信息优先使用 HEAD；Mihomo 管理面板读取流量头的示例见 [MetaCubeXD](https://github.com/MetaCubeX/metacubexd/blob/main/README.md)。本项目验证 HTTP 契约，不把模拟测试等同于真实客户端联网验收。

## 可读名称

`rule-providers` 使用规则增强原名、仓库引用名称；直接 URL 使用最后一个路径段，解码并去掉常见规则扩展名，不含 query。空名使用“远程规则”。逗号及控制字符规范化，避免破坏 RULE-SET 语法。

同一配置内重名按稳定资源身份分配 `(2)`、`(3)` 等后缀，并预留资源原名；重复使用同一规则和选项复用 provider。名称仅用于展示和配置引用，不用于鉴权或缓存身份。

## 清理边界

| 操作 | 结果 |
| --- | --- |
| 删除配置订阅 | 立即不可下载；清理 last-good、全部结构版本、迁移备份和配置刷新任务；保留用户 token、公共规则、30 天用户访问日志以及仍存在的节点源 |
| 删除规则增强 | 被任何配置或模板引用时返回 409；允许删除时清理该规则全部产物变体、刷新任务与不再共享的原文 |
| 修改/删除节点源或规则来源 | 撤销旧地址绑定；最后一个绑定消失后删除原文缓存，其他来源仍在使用的缓存保留 |
| 直接 URL / 仓库映射的公共产物不再被配置引用 | 作为独立公共资源保留，旧客户端持有效 token 仍可读；管理员在“系统 → 公共规则资源”清理，无需创建私有订阅资源 |
| 管理员删除公共产物 | 若配置或模板仍引用该规则则返回 409；否则删除该变体及最后的原文绑定。其他变体和规则增强定义保留；以后再次使用可重新生成 |
| 在途拉取/渲染结束 | 重新检查引用、文档及权限；无绑定的晚到缓存被清理，已删除的订阅/规则/刷新任务不会复活；删除并重建同 ID 也不能让旧规则请求或旧刷新任务重新落盘 |

删除节点源、组合也删除其刷新任务。队列执行前检查绑定和依赖，串行拉取每次 await 后检查配置是否变化，避免删除后继续请求后续来源。公共规则与刷新任务的删除监听仅在执行期间存在，完成即释放，不累积永久删除标记；已发送给上游的请求允许结束，但不能恢复已撤销的访问权限或已删除的产物。

仓库浏览缓存由仓库索引服务维护，公共产物的删除不等于删除仓库。配置内的节点 provider 保留最近 32 个结构版本；公共规则没有按配置堆积的历史版本。

## 接口与升级

- `GET /sub/:token/:profile`：主订阅，UA 自动选择 Mihomo / Stash。
- `GET /p/:token/:profile/:key?v=...`：配置节点产物；按目标保留结构版本。
- `GET /nodes/:token/:kind/:id`：所属用户的 source / collection / local 经处理链后的 Mihomo / Stash 节点，支持 HEAD 与流量头。
- `GET /r/:token/:key`：公共规则；目标由资源键确定，query 不能切换产物。
- `GET /rules/:token/:id`：公共规则增强的独立链接；按 UA 或 target/platform 选择 Mihomo / Stash 变体，与主订阅的规则引用共用公共产物。
- `GET /api/resource-links/:kind/:id`：登录后复制 sources / collections / locals / profiles / rulesets 链接，私有对象及节点依赖检查归属，公共规则使用当前用户 token；不拉取上游。
- `GET /api/profiles/:id/link`：登录后读取本人的配置链接。
- `GET /api/me/token`、`POST /api/me/token/reset`：读取、重置用户 token；重置 body 为当前 `{ token }`，过期值返回 409。
- `GET /api/system/rule-resources`、`DELETE /api/system/rule-resources/:key`：管理员管理公共产物。

升级事务为已有用户生成新凭证，撤销旧 `sub_tokens`，清理旧 last-good 与结构版本，保留配置、规则、节点、归属和有效原文。旧单订阅凭证不会升级为访问用户全部节点的凭证。所有客户端需重新复制订阅链接。旧 `/sub/:token`、无配置 ID 的 `/p`、按订阅管理 token 的 API 和带 token 的 `/api/rules/convert` 不再可用；登录态转换预览保留。

示例种子不含固定下载 token，导入时应指定已存在的用户名。旧种子里的 profileId token 被忽略，不扩大权限；无归属私有文档不能下载。完整主订阅仍未提供 Surge 输出。

## 验证

核心用例覆盖可读命名与冲突、统一托管、客户端转换和节点代理链；服务端覆盖同用户/跨用户权限、禁用与重置、v22 升级、公共产物复用、删除及在途竞争、历史节点依赖复核、失败恢复；前端运行现有弹窗架构和生命周期测试。浏览器记录见 [托管资源验收](../research/verification/managed-resources-20261030/README.md) 与 [本轮复核、复制链接与流量验收](../research/verification/managed-resources-review-20261030/README.md)。
