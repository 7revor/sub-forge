# 模板 YAML 导入

可以在「从 YAML 导入」窗口粘贴完整配置，也可以在模板「原始配置」视图直接粘贴。

## 提取规则

- 按原顺序保留 `proxy-groups`，组内只保留其他已定义组和 `DIRECT`、`REJECT`、`REJECT-DROP`、`PASS`，过滤单个节点。
- 移除组内 `use` 和 `include-all*` 节点相关字段。忽略顶层节点、节点订阅、DNS、端口等运行配置。
- `rule-providers` 保存名称、远程 URL 和定义顺序。第一版均作为远程来源，内容格式由现有流程自动识别，不沿用缓存路径、刷新间隔等客户端设置。
- 保留 `rules` 的匹配顺序、来源引用、组出口和最终 `MATCH`。同一 URL 的不同 provider 名称仍可以各自被规则引用。
- 完整配置中未引用的 provider 也保留，但不会生成新规则、参与匹配或触发发布时拉取。
- 支持来源、策略组及其成员中的常见 YAML 锚点与合并字段；模板自身的稳定 ID 注释继续保留。

独立组列表仍补入当前组；独立规则列表仍替换规则，两者都会保留来源定义。只导入 `rule-providers` 时沿用原功能：补入当前模板，并给新增 URL 添加出口为 `REJECT` 的规则。完整配置不使用这一追加行为。

## 缺失出口组

例如：

```yaml
rules:
  - RULE-SET,microsoft,🖥️ 微软服务
```

如果 `proxy-groups` 未定义「🖥️ 微软服务」，导入被阻止，错误显示行号、规则序号和缺失组名。必须先补齐同名策略组，或将出口改成已存在的组。导入不会自动创建策略组，也不会自动改写出口。

## 保存与兼容

模板新增可选 `ruleProviders` 数组保存来源目录；规则新增可选 `providerName` 保留 YAML 引用名称。实际远程规则身份、抓取和渲染仍以 matcher URL 为准。未使用的目录项不改变订阅输出。

来源目录随模板版本保存，编辑重载和版本差异均保留；既有模板无须迁移。导出的内部 `x-sub-forge-rulesets` 映射若与同名 provider 的 URL 不一致，会明确报错，避免悄悄使用旧链接。
