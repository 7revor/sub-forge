# 内核与客户端原文追加

2026-10-30。取代此前的公共基础配置映射及表单。规则、节点、策略组的领域模型继续使用。

## 编辑和保存

订阅的 `base` 直接保存两层原文结构：

```json
{
  "kernels": {
    "mihomo": "dns:\n  nameserver: [223.5.5.5]\n",
    "surge": "[General]\ndns-server = 223.5.5.5\n"
  },
  "clients": {
    "flclash": "port: 7890\n",
    "surge-macos": "[General]\nsocks5-listen = 127.0.0.1:7891\n"
  }
}
```

内核公共追加匹配同组客户端；客户端层可选，只匹配所选应用。2026-11-02 起，产品顶层分组统一为 Mihomo、Surge、Loon，Stash 位于 Mihomo 下并直接继承其公共 YAML，再应用 Stash 公共原文及 iOS/macOS 追加。[Stash 官方](https://stash.wiki/)仍称其为兼容 Clash 配置的自研内核，此处是项目的配置分组与继承约定；按用户要求不增加兼容过滤或字段转换。原有 `kernels.stash`、`clients.stash-ios`、`clients.stash-macos` 槽位保留，既有原文无需迁移。Surge 与 Loon 各自保存 INI。

编辑器只提供目标和文本框，不把原文解析为表单。原文的注释、空行、引号、未完成语法均直接保存；切换选项不改写或迁移文本。清空客户端选择只是切换编辑视图，已有内容仍保存并参与相应客户端生成；要移除某应用追加，应清空其文本框。

选中客户端时，编辑框上方按继承顺序显示默认折叠的只读原文区；Stash 公共页展示 Mihomo，Stash iOS/macOS 展示 Mihomo 与 Stash 公共两层。直接读取当前 `value`，因此未保存的内核草稿也会立即回显；不解析、不复制到客户端、不写回持久层。空内核显示「Mihomo 内核暂无公共配置」等提示。旁边说明 YAML 映射递归合并、数组整体替换及 INI 的覆盖规则。本轮不增加合并结果视图或逐字段覆盖标注。

订阅可用 `enabled:false` 暂停基础输出，暂停后保留原文，重新启用不会丢失数据。不补虚默认端口或 DNS。基础设置预设及其页面、接口、引用已移除，模板管理入口归入管理员分组；普通用户仍可在订阅中选择模板。

## 生成顺序与边界

1. 订阅内核公共原文。
2. 订阅客户端原文（可选）。

客户端层高于内核层。只处理命中目标的文本，其他内核或应用中未完成的文本不会影响当前输出。

Stash 的顺序为 **Mihomo 公共原文 → Stash 公共原文 → Stash iOS/macOS 原文（可选）**。缺省或空的下层继续继承上层；Mihomo 错误会使 Stash 生成失败，Stash 错误不影响 Mihomo、Surge、Loon。客户端覆盖过的字段遵循下述规则，未覆盖字段随内核更新。原文始终独立保存。

- YAML：映射递归合并，数组、标量及 `null` 整体替换；保留 `false`、`0`、空数组和含冒号/逗号的 DNS policy 键。输出会重新排版，保存的原文不变。重复键、循环别名、非映射顶层及非法键会报错。
- INI：只识别段落和必要的键。General、Host、MITM 同名键由后层替换，其余段落按顺序追加；不转换 DNS/Hosts 的值，保留原生指令及条件注释。重复键的合并不等于客户端语义校验。
- DNS 分流、加密 DNS、Hosts、IPv6、GeoData、系统代理跳过、TUN 排除和 fake-ip-range 全由对应原生配置决定。服务端不推测跨内核等价项，也不验证每项在客户端版本中的支持程度。
- `listeners` 在订阅追加中处理。
- 节点、节点集、策略组和规则由已有模块生成。追加中含 `proxies`、`proxy-providers`、`proxy-groups`、`rules`、`rule-providers` 或相应 INI 段时明确报错，不静默删段或覆盖生成结果。Surge 托管更新地址由服务生成，追加中不能再次声明 `#!MANAGED-CONFIG`。
- INI 测速 URL/超时只为已有节点、组输出读取必要的原生值；Loon 组间及全局超时冲突继续报错。

格式错误允许保存，但预览生成失败；正式订阅仅能回退到同一目标的最近成功产物。基础配置原文不是整份成品配置导入入口，不再提供独立的 Loon 完整导入。模板仅提取策略组、规则及规则集引用；节点与规则由各自模块解析，基础配置不解析成业务对象。

## 请求与预览

`target=mihomo|surge|stash|loon` 选择内核；`app` 选择可选客户端：`flclash`、`clash-verge`、`surge-ios`、`surge-macos`、`stash-ios`、`stash-macos`、`loon-ios`、`loon-macos`。不匹配的内核/应用组合返回错误。历史 `platform` 参数继续用于应用识别与日志，不参与规则转换。

常见 User-Agent 自动识别应用；无法识别应用时只使用对应公共追加。显式 `app` 优先；主订阅、节点资源、刷新链接和最近成功配置包含应用维度，避免借用另一应用的基础追加。完整订阅预览的顶层只有 Mihomo、Surge、Loon，Mihomo 下可选 Stash iOS/macOS，仍请求已有 Stash 输出目标；可留空应用只看 Mihomo 层。API 的 `target=stash`、原有 Stash 序列化和规则适配继续保留，不因界面分组改变。

## 规则只区分内核

规则改写条件只接受 `when.client`（历史字段名仍为 client，含义为输出目标）。规则集预览只提供 Mihomo、Surge、Loon，与基础配置顶层共用同一组选项，不再为 Stash 或其他应用提供独立预览按钮，也不发送应用或平台参数。已有 Stash 规则转换 API、资源身份、改写和订阅输出继续保留。同一输出目标的规则正文不按应用或平台拆分，PROCESS 及逻辑条件完整保留，是否执行由客户端及平台能力决定；不支持的语法仍按已有适配诊断。

不能用此变化推断每个客户端都会安全忽略所有未知规则；这里不新增版本/平台过滤器，也不拆掉逻辑条件放宽匹配。

## 升级

数据库 v28 在事务中备份受影响文档到 `native_migration_backups`，使用当前数据库密钥加密。保留原归属及更新时间；迁移失败整体回滚，重启后不重复转换原文。

- 旧原生对象转成对应内核文本；旧 `common` 只在这一次迁移中生成各端原文。正常编辑、保存和生成流程不再调用公共映射。
- 旧公共项与原生预设有交叉优先级时，将订阅有效配置展开为独立文本；不能等价迁移的值保留备份并显示诊断。旧版公共测速默认值不能自动变成 Mihomo/Stash 全局配置项，需在策略组确认。
- 删除预设前先备份原件（包括未引用的预设），再将已有引用按原优先级并入订阅：同层订阅优先、客户端层高于内核层。仅一个来源时原文逐字保留；多来源需合并 YAML / INI 结构。不完整语法无法合并时保留两份文本并提示修复，不静默丢弃。停用状态、归属与更新时间保留；新写入拒绝 `presetId`。历史种子导入也执行同一迁移。
- 旧的按平台限定的规则改写停用并备份，在规则集、模板或订阅显示迁移提示，避免删除条件后把作用范围扩大到整个内核。新 API 拒绝继续保存此类条件。
- 清理主配置 last-good，避免回退到旧公共转换结果；沿用主分支 v27 的无版本资源入口，节点和规则按当前订阅生成。升级后应刷新主订阅并核对预览。
