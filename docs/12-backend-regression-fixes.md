## 1. 修复后的行为

| 问题 | 修复与边界 |
| --- | --- |
| 远程规则错误页面被当作成功更新 | 文本规则按声明格式解析后才保存成功快照。空响应、HTML / JSON 错误页面、损坏的 YAML、无有效规则的内容记为失败，保留上一份可用快照。部分规则可解析时继续保留有效条目。旧库已有的无效远程快照在渲染时也会报错，走最近成功配置回退；没有可回退配置则返回 503。客户端覆盖明确丢弃所有有效规则仍被允许。 |
| 禁用规则仍拉取并拖累订阅 | 依据模板与个人覆盖合并后的实际规则收集依赖。禁用的私有规则、模板规则、覆盖层禁用项、锚点失效项和禁用的规则包子项不拉取；重新启用或另有启用引用时仍正常拉取。 |
| 同源多 URL 部分失败导致整份失败 | 同一源只要仍有一个 URL 的可用内容或成功快照，就继续渲染并报告告警。所有 URL 都无可用快照时维持失败与配置回退。组合成员整体不可用时仍失败，没有加入 COL-05 的可选跳过策略。 |
| 新模板发布绕过规则可用性检查 | 即时校验、影响分析与发布均检查启用的文本规则集及规则包子项，不依赖已有 Profile 引用。不可用的本地内容或没有可用快照的远程规则阻止发布，`force` 不能跳过自身错误。有旧快照时允许发布并告警；过期快照沿用后台刷新策略。二进制透传不下载，报告明确标注内容与可达性由客户端检查。 |
| 流量信息被缓存固化或覆盖 | 配置缓存命中时重新取最新快照的流量、更新当前拉取告警，并保留内核报告；同步写入 last-good 和保留版本。上游移除流量头时也移除旧值。每个源内不同 URL 的流量相加，到期取最早值，再按 Profile 设置汇总或选择指定源；同源重复 URL、重复引用同一源不重复累加。流量变化不增加结构版本。 |
| 非法处理器参数返回 500 | 创建、更新与逐步预览使用同一校验：检查所有现有处理器的数组、对象、标量、枚举、正则及 flags，返回包含步骤和字段位置的 400；拒绝写入无效处理链。禁用步骤同样要求合法结构。保留空数组、空正则占位与原有脚本编写权限。 |

纯域名解析保留域名通配符、国际化域名、内网单标签及现有前缀写法。规则 YAML 要求 `payload` 为字符串数组，避免把错误对象字符串化为规则。远程空规则集按不可用内容处理；需要停用规则时使用现有的禁用或客户端覆盖功能。
